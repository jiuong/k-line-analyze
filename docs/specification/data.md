# Module: Data (FR-1)

Maps to: [`../requirements.md`](../requirements.md) § FR-1.  
Parent goal: [`../goal.md`](../goal.md).

## Purpose

Load OHLC bars for `symbol + timeframe` over a time window (or last-N) from the MT5 microservice, persist successful pulls locally, and serve later reads from local storage when possible (including offline).

## Responsibilities & non-goals

| In scope | Out of scope |
|----------|--------------|
| Shared MT5 HTTP client for bars | Becoming a second market-data authority |
| Local persist + read-through / offline when coverage exists | WebSocket / push streams |
| Fixture dump CLI and loaders | Non-JSON engines (SQLite, etc.) in this phase |
| Gitignore policy for bulk dumps | Tick streams / multi-broker aggregation |

## MT5 service calls

### HTTP endpoint

```http
GET {MT5_BASE_URL}/symbols/{symbol}/bars?timeframe=…&from=…&to=…&count=…
```

| Query | Type | Notes |
|-------|------|-------|
| `timeframe` | string | Required; MT5 `TimeFrame` |
| `from` | Unix seconds | Range start when present |
| `to` | Unix seconds | Range end; omit = now on server |
| `count` | int | Last-N mode |

Path: encode `+` in symbols (e.g. `XAUUSD%2B`). Alias resolution is server-side; prefer `meta.symbol` when echoing resolved names.

### Client API ([`src/data/fetchBars.ts`](../../src/data/fetchBars.ts))

| Export | Role |
|--------|------|
| `fetchBars(params, options?)` | Returns `Bar[]` |
| `fetchBarsWithMeta(params, options?)` | Returns `{ data, meta }` |
| `Mt5ApiError` | Typed API error (`code`, `status`, `message`) |
| `barsFixtureFileName(params)` | Default on-disk fixture basename |

Params: `FetchBarsParams` — `{ symbol, timeframe, from?, to?, count? }` ([`src/types/bars.ts`](../../src/types/bars.ts)).

Options: `baseUrl?`, `fetchImpl?` (defaults: `process.env.MT5_BASE_URL`, global `fetch`).

### Fetch behaviors

- Accept HTTP 200 with `meta.degraded` (service local fallback).
- Propagate network / 4xx / 5xx as `Mt5ApiError` or equivalent; never invent bars.
- Unit tests mock HTTP; do not hit live MT5 in CI unit tests.

## On-disk conventions

### Filename

Generated by `barsFixtureFileName(params)`:

- Range mode: `{symbol}_{timeframe}_{from}_{to}.json` (`to` may be `now` when omitted in the name helper)
- Count mode: `{symbol}_{timeframe}_count{N}.json` (default N = 100)

Unsafe path characters in `symbol` are sanitized to `_`.

### JSON shape (`BarsFixtureFile`)

Aligned with the MT5 API envelope:

```ts
{
  data: Bar[];           // OHLC (+ optional volume fields)
  meta: BarsMeta;        // symbol, timeframe, count, source, degraded, …
  pulledAt?: TimeString; // ISO-8601 UTC when written by pull-bars
}
```

### Readers

| Export | File | Returns |
|--------|------|---------|
| `loadBarsFixture` | [`src/data/loadBarsFixture.ts`](../../src/data/loadBarsFixture.ts) | `Bar[]` |
| `loadBarsFixtureFile` | same | full `BarsFixtureFile` |
| `loadBars` / `loadBarsWithMeta` | [`src/data/loadBars.ts`](../../src/data/loadBars.ts) | Product read-through (`Bar[]` or envelope + `source`) |

Fixture paths may be absolute or relative to `process.cwd()`. Prefer `loadBars` for product reads (`refresh?`, `storeRoot?`, MT5 options).

### Keying & read path (target)

- Retrievable at least by `symbol + timeframe + time range` (or count window) via `barsFixtureFileName` / `barsStorePath`.
- Target flow: **local hit → miss or explicit refresh → MT5 → write-back**.
- Offline: if MT5 is down and local data **covers** the query window, return local data.

### Coverage (v1) — `barsCoverQuery`

Endpoint coverage only (no session-gap scan):

| Mode | Rule |
|------|------|
| Count (`count` set) | `bars.length >= count` (takes precedence if also range fields present) |
| Range | Requires `from`; empty → false; `min(time) <= from`; if `to` set, `max(time) >= to`; omit `to` → start check only |

Helper: [`src/data/barsCoverage.ts`](../../src/data/barsCoverage.ts).
